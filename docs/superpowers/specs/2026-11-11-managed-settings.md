# Управляемые проекты: первый сквозной сценарий

Согласовано в обсуждении: интерфейс доступен без проектов; администратор добавляет GitLab-подключение и проект, проверяет готовность и включает выполнение без перезапуска. PostgreSQL — источник управляемых настроек, bootstrap остаётся в окружении. Текущая задача не меняет конфигурацию во время исполнения.

## Граница первой версии

Опциональный managed-режим для internal PostgreSQL. Существующий env/fleet runtime не меняет поведение. Подключения GitLab, подготовка checkout, проекты, команды проверок, модель/тайм-аут и пауза доступны в UI. Telegram, Yandex bridge, PM и общесистемные редакторы настроек в этом режиме пока не активируются; старый режим сохраняет их. Не выдавать этот этап за перенос всех настроек.

## Решения

Версионируемый реестр в PostgreSQL, optimistic concurrency, отдельная desired/active конфигурация проекта. Токены шифруются AES-256-GCM с внешним ключом и никогда не возвращаются браузеру. URL ограничены HTTPS origin allowlist администратора сервера; редиректы запрещены. Доступ — существующая авторизация human API, изменения только admin, запрет agent token. UI скрыт от неадминистратора, но backend — обязательная граница.

Новый проект создаётся выключенным. «Сохранить и применить» ставит конфигурацию на подготовку; worker применяет её на границе запусков. Ошибка подготовки сохраняет прежнюю active-конфигурацию. Остановка проекта запрещает дальнейший dispatch после наблюдения изменения, не убивает текущий процесс. Checkout формируется только под заданным сервером корнем по UUID проекта, не по имени/пути из формы. Никакого автоматического запуска скриптов репозитория при подключении.

Runtime берёт снимок конфигурации на цикл задачи. Подготовка и исполнение одного проекта используют общий PostgreSQL advisory lock; оно не заменяет task/repository leases. Не допускается автоматическое переключение конфигурации возобновляемой сессии: событие задачи сохраняет несекретный снимок параметров; resume/review используют его после рестарта. Подключение остаётся живой ссылкой, новый токен не фиксируется в истории задачи. Отзыв доступа и процессная изоляция не обещаются этим PR.

## Не входит

Полноценный SaaS, новый пользовательский IAM, автоматический OAuth login Codex, автодеплой, cross-repository задачи, независимый reviewer, импорт всех YAML настроек, fault-tolerant distributed config rollout. Для trusted proxy остаётся обязанность исключить прямой доступ к backend.

## Приёмка

Нулевой реестр не блокирует HTTP; настройки сохраняются после нового подключения к БД; секретов нет в DTO/ошибках; неверный токен не заменяет рабочий; повторная/конкурентная запись отклоняется; один проект не портит другой; применённая версия видна; текущий запуск использует старый снимок, следующий — новый; frontend маршруты до :taskId; старые тесты остаются зелёными.
