# Консоль задач (Angular/PrimeNG)

Это веб-интерфейс внутреннего task tracker. Он показывает задачи, историю исполнения и действия человека, используя API Node.js-воркера.

## Разработка

Сначала запустите Node.js observability/human API на `127.0.0.1:9464`, затем:

```bash
npm --prefix web ci
npm run web:dev
```

Angular dev server доступен по `http://127.0.0.1:4200/tasks`. Запросы `/api` проксируются к backend через `web/proxy.conf.json`.

## Рабочие сценарии

- **Очередь.** Поиск по названию, ID, имени или пути GitLab применяется ко всем задачам. Следующая страница открывается кнопкой «Показать ещё». Репозиторий выбирается из списка. Фильтры и выбранная задача отражаются в URL.
- **Карточка задачи.** На широком экране карточка открывается рядом со списком. На узком экране «К очереди» возвращает к той же выдаче и выбранной строке. В сохранённом черновике можно изменить название, описание и критерии. Для задачи, ожидающей ручной приёмки, карточка показывает MR, критерии и действие «Принять результат».
- **Новая задача.** Нажмите «Создать задачу» в очереди. В управляемом режиме выберите «Репозиторий» по имени или пути GitLab. Список содержит включённые проекты с применёнными настройками. Из карточки проекта в настройках можно открыть эту же форму с предвыбором репозитория.
- **Цели и предложения.** Выберите репозиторий перед запуском анализа или стратегии. Готовый результат стратегии содержит ссылки на созданные цели. Ссылки возврата восстанавливают фильтры исходного списка. Права на запуск и принятие решений определяет сессия.
- **Операции.** «Требуют внимания» объединяет вопросы и текущие сбои по задачам. Счётчики задач открывают очередь с фильтрами, сведения о воркерах и арендах остаются на странице. Кнопка «Детали» открывает диагностику. После закрытия фокус возвращается к кнопке.
- **Настройки.** Администратор управляет подключениями GitLab, командами проверок и лимитами исполнителя отдельно для каждого проекта. [Порядок подключения](../docs/MANAGED_SETTINGS.md#порядок-добавления-проекта)

## Проверки и сборка

```bash
npm run web:typecheck
npm run web:test
npm run web:build
npm run web:e2e
```

Браузерные E2E-тесты используют Playwright и требуют установленного browser runtime. Они проверяют сценарии задач, статусы с учётом ролей, переходы по глубоким ссылкам, базовую доступность и адаптивность.

Для визуальной проверки без рабочего API выполните `npm run web:build`, затем `node web/e2e/mock-console-server.mjs` и откройте `http://127.0.0.1:4308/tasks/`. Стенд показывает тестовые данные наблюдателю. Сценарии с правами разработчика и оператора и настройка проектов запускаются в E2E.

Чтобы на локальном стенде увидеть «Создать задачу» и проверить выбор одного из двух тестовых репозиториев, запустите его в PowerShell с параметрами ниже. Созданные задачи хранятся в памяти этого процесса.

```powershell
$env:E2E_PORT = '4341'
$env:E2E_MANAGED_PREVIEW = '1'
node web/e2e/mock-console-server.mjs
```

Для проверки добавления репозитория запустите стенд администратора из корня репозитория командой `node --import tsx web/e2e/managed-console-preview.mjs`. После сборки интерфейса страница настроек доступна на `http://127.0.0.1:4347/tasks/settings`. В настройках уже есть тестовое подключение GitLab. Репозитории, проверки исполнения и токен демонстрационные, изменения хранятся в памяти.

### План проверки интерфейса по этапам

1. Откройте очередь на широком и узком экране. Найдите старую задачу по пути репозитория в наборе больше 100 задач. Откройте строку и вернитесь. Проверьте URL, сохранённые фильтры, фокус и отсутствие повторного запроса списка при выборе задачи.
2. Откройте задачу с вопросами. Выберите вариант у второго вопроса и проверьте адресацию ответа. После записи откройте историю и найдите сохранённый ответ.
3. Создайте черновик, измените критерии, перечитайте карточку и поставьте задачу в очередь. Для задачи после merge проверьте приёмку и запись результата в истории. В настройках сохраните новую ветку и сравните её с веткой для новых задач до применения.
4. Откройте цель и её связанные предложения. Проверьте запуск стратегии, видимость действий для разных ролей и подтверждение решения по предложению. В операциях откройте диагностику сбоя и закройте её клавишей Escape.
5. Повторите сценарии на ширинах 320, 760 и 1440 px. Проверьте длинные заголовки, фокус и отсутствие горизонтальной прокрутки всей страницы. Сравните снимки одинаковых состояний до и после изменения. После правок повторите затронутый сценарий и полный набор E2E.

Production-сборка находится в `web/dist/task-tracker-console/browser`. Чтобы Node.js выдавал её по `/tasks`:

```env
TASK_TRACKER_UI_STATIC_DIR=web/dist/task-tracker-console/browser
```

## Аутентификация

Angular-клиент **не хранит bearer-токены**. Используйте разрешённый localhost-режим для разработки или закрытый reverse proxy, который проверяет пользователя и передаёт доверенные заголовки/авторизацию на backend. Нельзя публиковать UI/API с произвольно подставляемыми клиентом служебными заголовками.

Общие правила доступа и запуска — в [руководстве по наблюдаемости](../docs/OBSERVABILITY_RUNBOOK.md) и [конфигурации](../docs/ENV_CONFIGURATION.md).
